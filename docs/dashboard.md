# Кабинет FreeNETvpn

[English account guide](accounts.en.md) · [Пользователи и права](accounts.ru.md) · [Инструкции устройств](devices.ru.md)

Откройте `https://DOMAIN/admin`, войдите с логином и паролем установки. Кабинет работает на компьютере и телефоне; все стили, скрипты и QR-коды обслуживает ваш сервер.

## Что доступно

- **Обзор:** состояние шести протоколов, запуск, остановка и перезапуск, сведения о диске и времени работы сервера. Состояние контейнера не заменяет проверку подключения из внешней сети.
- **Клиенты:** поиск, фильтр по протоколу, создание и отзыв отдельных подключений, получение файла и QR-кода. Для IKEv2 скачивается ZIP с учётными данными, CA и Apple-профилем. L2TP экспортируется как JSON с параметрами подключения.
- **Шаблоны:** три готовые настройки VLESS и три AmneziaWG. Шаблон можно выбрать при создании или изменить у существующего клиента. После изменения скачайте профиль заново и импортируйте на устройстве.
- **Резервные копии:** создание и скачивание архива с настройками, клиентами и ключами. Во время создания VPN и кабинет кратко останавливаются. После запуска кабинета может потребоваться повторный вход; результат остаётся в журнале. Восстановление выполняется на сервере в пустую установку.
- **Журнал операций:** очередь и результаты последних операций. Двойная отправка одного запроса не запускает операцию повторно. После перезапуска агента незавершённые операции получают статус «Прервано», чтобы можно было проверить результат перед повтором.

Для WireGuard сначала завершите родной мастер на `https://WG_DOMAIN/`. Затем нажмите «Подключить wg-easy» в кабинете и введите **внутреннюю** учётную запись wg-easy. Она может отличаться от учётной записи FreeNET. После этого создание, экспорт и отзыв клиентов доступны в общем списке. Для включения протокола, который не был установлен, используйте `tools/manage.py services` и повторный запуск установщика.

Имена создаваемых клиентов: 1–32 латинских буквы, цифры, дефис или подчёркивание. Создавайте отдельный профиль для каждого устройства. Основной профиль VLESS (`legacy`) сохраняется при обновлении; его ротация остаётся отдельной серверной операцией.

## Шаблоны

| Протокол | Шаблон | Настройки |
| --- | --- | --- |
| VLESS | Универсальный (`ws-tls`) | WebSocket / TLS, 443, проверка сертификата |
| VLESS | Мобильная сеть (`mobile-ws`) | WebSocket / TLS; TCP keep-alive 30 с в Xray JSON |
| VLESS | HTTP/2 · gRPC (`grpc-tls`) | gRPC / TLS, 443; требуется поддержка gRPC клиентом и сетью |
| AmneziaWG | Сбалансированный (`balanced`) | MTU 1280, keep-alive 25 с, Jc 4, Jmin 40, Jmax 70 |
| AmneziaWG | Мобильная сеть (`mobile`) | MTU 1200, keep-alive 15 с, Jc 4, Jmin 40, Jmax 70 |
| AmneziaWG | Меньше служебного трафика (`economy`) | MTU 1280, keep-alive 0, Jc 1, Jmin 20, Jmax 40 |

У мобильного VLESS-профиля **URI/QR содержит обычный WS/TLS**: для TCP keep-alive используйте кнопку «Xray JSON». AmneziaWG-клиент должен поддерживать S1–S4 и H1–H4. Шаблоны меняют клиентские MTU, keep-alive и J-параметры; общие S/H и ключи сервера сохраняются. Частый keep-alive увеличивает служебный трафик и может расходовать больше батареи. Нулевой keep-alive допускает закрытие NAT-сессии при простое. Доступность через фильтрацию конкретной сети проверяйте отдельно.

То же через CLI:

```bash
sudo python3 tools/manage.py client add vless phone --preset grpc-tls
sudo python3 tools/manage.py client add amnezia travel --preset mobile
sudo python3 tools/manage.py client preset amnezia travel --preset economy
sudo python3 tools/manage.py client export vless phone
```

Создание/отзыв клиента или смена транспорта VLESS пересоздаёт Xray и кратко прерывает его подключения. IPsec и AmneziaWG также пересоздаются при изменении списка клиентов. Смена только шаблона AmneziaWG пересоздания сервера не требует. IKEv2 и L2TP используют один контейнер: управление сервисом затрагивает оба протокола.

## Обновление существующей установки

Сделайте резервную копию, обновите checkout до проверенного коммита и запустите:

```bash
sudo bash install.sh --existing
sudo systemctl status freenetvpn-control --no-pager
```

Установщик сохраняет существующие ключи, UUID и клиентов, добавляет локальный агент управления и пересоздаёт контейнер кабинета. Аутентификация использует прежний пароль. Устаревшие параметры окружения v1 автоматически не переносятся — смотрите [migration.md](migration.md).

Если кабинет сообщает, что сервис управления недоступен:

```bash
sudo systemctl status freenetvpn-control --no-pager
sudo journalctl -u freenetvpn-control -n 50 --no-pager
sudo bash scripts/install_control.sh
sudo python3 tools/manage.py compose up -d --force-recreate admin
```

Последняя команда обновляет привязку сокета, если его каталог был пересоздан. Рабочая установка использует каталог `/run/freenetvpn` и сокет `control.sock`. Root-операции CLI лучше выполнять после завершения очереди кабинета; изменения клиентов сериализуются между агентом и CLI.

## Границы доступа

Веб-контейнер работает от UID 10001, с файловой системой только для чтения и без Docker socket. Он обращается к локальному systemd-агенту через Unix socket с правами 0660 и отдельным секретным токеном. Агент принимает только операции из фиксированного списка; имена сервисов и команды задаются кодом. TCP-порта, терминала и загрузки произвольного shell-кода у агента нет.

Сессия кабинета действует восемь часов; cookie использует Secure, HttpOnly, SameSite=Strict. Изменения требуют совпадающего Origin и CSRF-токена. Сохраняется Basic Auth для CLI и внешней защиты wg-easy; для изменения через Basic API также нужен `X-FreeNET-Request: 1`. Пароли и экспортированные конфигурации не входят в обзор и журнал; они выдаются только отдельным авторизованным запросом. Внутренний пароль wg-easy хранится в приватном `data/protocols.json` для выполнения разрешённых операций и попадает в защищённую резервную копию.

Workspace 3 поддерживает несколько администраторов и обычных пользователей с назначенными профилями. Исходный владелец защищён от удаления. Сервер остаётся один; мультисерверность и биллинг не входят в эту версию. См. [пользователи и права](accounts.ru.md).
