# Пользователи и права

[English](accounts.en.md) · **Русский** · [На главную](../README.ru.md)

| Возможность | Администратор | Пользователь |
| --- | --- | --- |
| Управление сервером, VPN-профилями, аккаунтами и архивами | Да | Нет |
| Скачивание профилей и QR | Все профили | Только явно назначенные |
| Родной интерфейс wg-easy | Да, с внутренним аккаунтом | Нет |
| Инструкции и переключение RU/EN | Да | Да |
| Смена своего пароля | Дополнительные аккаунты; владелец — через конфигурацию сервера | Да, с текущим паролем |

Владелец установки — исходный администратор из .env. Его доступы и VPN-ключи сохраняются при обновлении. Его нельзя удалить, отключить или понизить из кабинета. Дополнительные администраторы получают полный доступ к серверу и всем профилям; роль пользователя предназначена для подключения устройств.

## Добавить человека

1. Создайте отдельный VPN-профиль устройства в **Подключениях**.
2. Откройте **Пользователи → Добавить пользователя**, укажите имя и уникальный логин: 1–64 латинских буквы, цифры, дефис или подчёркивание.
3. Выберите **Пользователь** для скачивания своих профилей или **Администратор** для управления. Укажите язык по умолчанию и пароль от 16 символов.
4. Отметьте доступные пользователю профили. Администратор получает все профили. Аккаунт без назначений увидит сообщение о необходимости обратиться к администратору.
5. Сохраните и передайте первоначальные доступы лично. Все входят по одному адресу /admin; содержимое кабинета зависит от роли. Пароль меняется через кнопку аккаунта.

## Изменить доступ, сбросить пароль, удалить

Нажмите **Управлять доступом**. Можно изменить имя, роль, язык, назначения и разрешение входа. Для сброса введите новый пароль; пустое поле сохраняет прежний. Сохранение меняет ревизию аккаунта и завершает старые сессии. Удаление или понижение самого себя и изменение владельца отклоняются. В журнале сохраняются автор, действие и аккаунт, но не пароли.

**Вход в кабинет и VPN-доступ — разные вещи.** Отключение/удаление аккаунта или снятие назначения не стирает ключ, уже импортированный на устройство. Для прекращения VPN отзовите профиль в «Подключениях». Сервис может перезапуститься и кратко прервать другие соединения. Если один профиль выдан нескольким людям, отзыв отключает его у всех; предпочтителен отдельный профиль на устройство.

Назначение привязано к идентификатору ключа, а не только имени. Пересозданный профиль нужно выдать заново. Удаление и создание аккаунта с прежним логином не восстанавливает старые сессии. Язык, выбранный в браузере, сохраняется локально и имеет приоритет над языком по умолчанию.

## Обновление и восстановление

Сначала создайте и скачайте резервную копию. Обновите полный исходный код по [инструкции развёртывания](deployment.md), сохранив .env, data, runtime и backups. Выполните `sudo bash install.sh --existing`: агент будет перезапущен, веб-контейнер пересобран. Сама команда код не скачивает. После обновления войдите заново; пароль владельца остаётся прежним.

Дополнительные аккаунты, назначения и журнал находятся в приватном data/control/accounts.json и включаются в стандартный архив. Для восстановления нужен чистый проект этой версии без .env/runtime/data: `sudo bash restore.sh /путь/к/архиву.tar.gz`, проверка DNS, затем `sudo bash install.sh --existing`. Проверьте подключения перед отключением прежнего сервера. Архивы и экспортированные профили содержат секреты — не размещайте их в GitHub.

Веб-контейнер остаётся без root и записи на диск; аккаунты сохраняет локальный Unix-агент. Запись, операции профилей и копирование сериализованы. Проверка роли применяется к сессиям, Basic Auth, QR, скачиванию и прямым API-запросам. Обычным пользователям недоступны чужие профили, аккаунты, архивы и управление сервером.
