# Ошибка установки: исправление и продолжение

[English](installation-errors.en.md)

Установщик сообщает код ошибки, наблюдаемую причину, способ проверки и команду повтора. Русские подсказки: `sudo env FREENET_LANG=ru bash install.sh` (добавьте `--existing`, если `.env` уже сохранён). Английские: `FREENET_LANG=en`. По умолчанию язык определяется по `LANG`.

## Одинаковые домены — это ошибка ввода, а не DNS

Если оба поля заполнены `magic.llnit.com`, сообщение `CONFIG_HOSTS_EQUAL` означает, что кабинет и WireGuard UI нельзя разместить под одним именем. DNS на этом этапе ещё не проверялся. В новой версии повторно запрашивается только ошибочное имя, до ввода пароля.

Используйте, например:

| Поле | Значение | DNS |
|---|---|---|
| DOMAIN — кабинет VPN | `magic.llnit.com` | A → публичный IPv4 этой машины |
| WG_DOMAIN — интерфейс WireGuard | `wg.magic.llnit.com` | A → тот же IPv4 |

Записи создаются в панели вашего DNS-провайдера. Имя записи зависит от редактируемой зоны: для зоны `llnit.com` это обычно `magic` и `wg.magic`. IP возьмите из панели именно устанавливаемого VPS. Не вводите `https://`, порт или путь.

В старой версии ошибка `WireGuard UI needs its own hostname (WG_DOMAIN)` завершает ввод после пароля, но до сохранения новой `.env`. Исправьте второе имя и повторите установку без `--existing`. Ожидание DNS само по себе не исправит одинаковые значения.

## DNS, HTTPS и сервисы

| Код | Что установлено | Что исправить и проверить |
|---|---|---|
| `CONFIG_DOMAIN` | Неверный формат имени | Введите имя вида `vpn.example.com`, без схемы/порта/пути. |
| `DNS_NO_IPV4` | Резолвер сервера не вернул IPv4 | Проверьте A-запись, имя, делегирование зоны и резолвер. При недавнем изменении возможна задержка кэша. Повторите `getent ahostsv4 ИМЯ`. |
| `DNS_LOOKUP_FAILED` | Проверка резолвера завершилась ошибкой/таймаутом | Проверьте сеть и DNS сервера. Это не доказывает отсутствие записи у провайдера. |
| `HTTPS_DNS` | curl не разрешил домен | Повторите проверку DNS; после исправления запись должна возвращать IP VPS. |
| `HTTPS_CONNECT` / `HTTPS_TIMEOUT` | Нет соединения или ответа за отведённое время | Сравните IP, проверьте Caddy, входящие TCP 80/443 у провайдера и на машине. Проверьте из другой сети: серверу может мешать NAT loopback. |
| `HTTPS_TLS` | Ошибка TLS/проверки сертификата | Проверьте A/AAAA, 80/443, время сервера и причину ошибки выпуска в логах Caddy. Дождитесь успешной выдачи; не отключайте проверку TLS. |
| `HTTPS_BACKEND` | HTTPS вернул 502/503/504 | Проверьте admin/Caddy, для домена WireGuard — также wg-easy. Не сводите эту ошибку к распространению DNS. |
| `HTTPS_AUTH` | Без пароля не получен ожидаемый 401 | Проверьте, куда ведёт домен, маршруты Caddy/forward_auth и admin. Защита входа пока не подтверждена. |
| `HTTPS_RESPONSE` | Неожиданный статус или тело ответа | Убедитесь, что домен ведёт на эту установку: даже 200 может возвращать другой сайт. Проверьте маршруты и сервис admin. |
| `SERVICE_STOPPED` / `INSTALL_STAGE` | Не запущен сервис или завершился ошибкой указанный этап | Следуйте подсказке этапа и исходной ошибке выше. При занятом порте выполните `sudo ss -lntup` и определите владельца, прежде чем останавливать службы. |
| `INSTALL_DOWNLOAD` | Не завершена загрузка проекта/зависимостей | Проверьте ошибку APT/curl/tar, доступ к GitHub, свободное место и выбранную версию. Повторите исходную команду после исправления. |
| `CONFIG_READ` | Нет корректной сохранённой конфигурации | Если `.env` есть, запустите `sudo python3 tools/manage.py validate` и исправьте указанное поле. Если файла нет — повторите обычную установку. |

Проверка DNS выполняется **до установки Docker и загрузки образов**, но после сохранения настроек. Она выводит адреса, видимые с сервера; сравните их с панелью VPS. Она не подтверждает распространение зоны по всему миру, доступность входящих портов или правильность каждого AAAA-ответа. Неработающую AAAA-запись исправьте либо удалите, если IPv6 для сервиса не используется.

## После исправления

Перейдите в каталог установки (обычно `/opt/freenetvpn`; при другом `INSTALL_DIR` используйте его). Если `.env` **ещё нет**, повторите ввод:

```bash
cd /opt/freenetvpn
sudo env FREENET_LANG=ru bash install.sh
```

Если `.env` **уже есть**, при ошибке ввода аккуратно измените только названные поля в `sudo nano .env`. Проверьте и примените сохранённые настройки:

```bash
cd /opt/freenetvpn
sudo python3 tools/manage.py validate
sudo env FREENET_LANG=ru python3 tools/diagnostics.py dns
sudo env FREENET_LANG=ru bash install.sh --existing
```

Если ранее использовали `--no-firewall`, сохраните этот флаг в повторном запуске. Не удаляйте `.env`, `data/`, ключи, пользователей и резервные копии. `--existing` повторяет установочные этапы и пересоздаёт контейнеры: уже работающие подключения могут кратковременно прерваться. Для одной проверки без переустановки используйте `sudo bash scripts/health_check.sh`.

Для локального разбора запуска:

```bash
sudo python3 tools/manage.py compose ps
sudo python3 tools/manage.py compose logs --tail 60 caddy admin
```

Для WireGuard добавьте `wg-easy` к списку сервисов. Не публикуйте полные журналы с личными данными. Установщик не печатает командную строку упавшей команды и не отключает TLS, однако вывод сторонних APT/Docker/сервисов следует проверять перед отправкой.

`--existing` **не скачивает новый код**. Для получения новой диагностики обновите код по [инструкции развёртывания](deployment.md), сохраняя состояние. Повторный запуск скачанного загрузчика также использует уже существующий каталог. Успешные серверные проверки не заменяют проверку подключения и трафика с клиентского устройства.
