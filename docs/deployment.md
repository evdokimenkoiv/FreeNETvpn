# Установка, обновление и проверка

Главная точка входа — **`install.sh`**. Команда для чистого сервера находится в [README](../README.md#быстрое-развёртывание); она сохраняет stdin терминала для интерактивных вопросов. Не заменяйте её на `curl | bash`: установщику нужен ввод доменов и пароля.

## До запуска

Поддерживается Ubuntu 22.04/24.04/26.04 LTS x86_64 с systemd, доступом root/sudo и публичным IPv4. Windows, macOS, контейнер без systemd и произвольный Linux этой командой не поддерживаются. Для полного комплекта нужна x86_64 из-за закреплённого образа Outline.

1. Подготовьте DNS A для основного домена и отдельного домена wg-easy на один IP сервера. Если IPv6 не настроен, удалите AAAA. Для UDP-протоколов нужен прямой IP endpoint.
2. Откройте firewall провайдера: TCP 80/443, UDP 51820 (WireGuard), UDP 500/4500 (IKEv2 и L2TP), TCP/UDP 2443 (Outline), UDP 51830 (AmneziaWG). Это значения по умолчанию; выбранные порты указаны в `.env`. Порт API Outline 19090 наружу не открывается.
3. Используйте свободные порты на сервере. Если там уже есть другой VPN или веб-сервер, сначала определите отдельные порты/машину; установщик не удаляет чужие сервисы.

После команды установщик спросит два домена, email и пароль администратора. Он установит зависимости и Docker Compose, создаст конфигурацию и ключи, подготовит firewall, проверит Xray/Caddy, запустит контейнеры и локальный агент, проверит HTTPS и авторизацию. Изменения SSH-аутентификации/порта не выполняются.

Завершение обозначается сообщением `Panel ready: https://DOMAIN/admin`. Ошибка возвращает ненулевой код. Повторная команда сохраняет существующие ключи и клиентов. Загрузка проекта выполняется во временный каталог и становится установкой только после успешной распаковки; неудачная загрузка допускает повтор.

## Первый клиент

1. Откройте `https://DOMAIN/admin`, логин `admin` и пароль установки.
2. Для VLESS/AmneziaWG выберите «Создать клиента», протокол и шаблон, затем импортируйте профиль/QR. Для мобильного VLESS keep-alive нужен экспорт **Xray JSON**.
3. Для WireGuard откройте `https://WG_DOMAIN/`, пройдите внешнюю авторизацию FreeNET и родной мастер wg-easy. Укажите endpoint=`DOMAIN`, порт=`WG_PORT`, DNS из `.env`. Затем подключите **внутреннюю** учётную запись wg-easy в кабинете FreeNET.
4. Для IKEv2 импортируйте CA и задайте удалённый идентификатор сервера. Для L2TP используйте экспортированные параметры IPsec/PPP; для Outline — ссылку доступа. Подробности: [протоколы](protocols.md), [кабинет](dashboard.md).
5. Проверьте интернет и DNS с устройства в другой сети. Зелёный статус сервиса не означает, что firewall провайдера пропускает VPN.

## Обновление

Используйте [обновление одной командой](update.ru.md) ([English](update.en.md)): оно сохраняет настройки/пользователей, создаёт согласованную резервную копию, поддерживает продолжение после сбоя и явный откат. Это заменяет ручное наложение архива и git pull на сервере. Обновление требует окна обслуживания.

`--existing` у install.sh применяет уже установленный код, но не скачивает исправления. Для получения нового кода используйте update.sh. После первой установки новой версии короткая команда: `sudo bash /opt/freenetvpn/update.sh`.

## Если запуск не завершился

[Коды ошибок и команды продолжения](installation-errors.ru.md) · [English recovery guide](installation-errors.en.md).

Одинаковые DOMAIN и WG_DOMAIN — ошибка ввода до проверки DNS. Укажите разные имена; обе A-записи могут вести на один IPv4. После сохранения `.env` исправляйте только нужные поля и продолжайте с `--existing`.

```bash
cd /opt/freenetvpn
sudo bash scripts/health_check.sh
sudo python3 tools/manage.py compose ps
sudo systemctl status freenetvpn-control --no-pager
sudo journalctl -u freenetvpn-control -n 50 --no-pager
```

При ошибке HTTPS проверьте DNS, доступность 80/443 извне и отсутствие занятого порта. При ошибке туннеля проверьте UDP/TCP-порт протокола в firewall провайдера и настройки клиента. При недоступном кабинету агенте повторите `sudo bash install.sh --existing`. Диагностические журналы могут содержать адреса клиентов: не публикуйте их целиком.

CI проверяет загрузчик на изолированных фикстурах, systemd-агент и реальные VPN-контейнеры на двух Ubuntu. Полный запуск root-установщика на отдельном VPS, публичная выдача сертификатов, перезагрузка сервера и внешние клиентские приложения проверяются по [acceptance.md](acceptance.md).
