# Обновление одной командой

[English](update.en.md)

Для существующей установки в `/opt/freenetvpn`, включая версии, где ещё нет `update.sh`:

```bash
sudo bash -c 'set -e; f=$(mktemp); trap "rm -f -- \"$f\"" EXIT; curl -fsSL --retry 3 https://raw.githubusercontent.com/evdokimenkoiv/FreeNETvpn/main/update.sh -o "$f"; bash "$f"'
```

Когда новый файл уже установлен, достаточно `sudo bash /opt/freenetvpn/update.sh`. Это тоже получает свежий механизм обновления. Для другого каталога добавьте `INSTALL_DIR=/ваш/каталог` через `sudo env` перед `bash`. `FREENET_REF=ПРОВЕРЕННЫЙ_SHA` позволяет выбрать конкретную версию; по умолчанию используется `main`. Выбирайте версию с успешным CI. Проверка наличия новой версии в кабинете остаётся отдельной операцией без установки.

Обновление требует существующей корректной `.env`, Python 3, curl, Docker и Ubuntu/systemd. Оно не создаёт новые пароли, ключи или аккаунты. Для незавершённой установки после ошибки скачивания образов сначала устраните её причину. При недостатке диска сначала освободите место: обновление тоже требует места для копии.

## Что происходит

1. Определяется точный commit и скачивается архив этой версии. Проверяются пути архива, настройки на отдельной копии, место на диске и локальные изменения управляемых файлов. Ошибка до остановки не затрагивает работающие сервисы.
2. Сервисы и локальный управляющий агент останавливаются. Это прерывает VPN-подключения на время копирования, скачивания/сборки образов и проверок; запланируйте окно обслуживания и завершите операции в кабинете.
3. В `.updates/ID/` сохраняются приватная копия состояния `state.tar.gz` (`.env`, `data`, `runtime`), предыдущие заменяемые файлы `old-code/` и автономный `updater.py`. Копия включает пользователей, права, назначения, VPN-ключи и состояние WireGuard. Каталог доступен только root; его нельзя скачать через кабинет. Перенесите копию на отдельное хранилище приватным способом.
4. Обновляются только файлы проекта; `.env`, `data`, `runtime`, `backups` и `.git` не заменяются архивом. Генерируемые файлы `runtime` обновляет штатный установщик из сохранённых настроек. Удаляются только устаревшие файлы из манифеста предыдущего обновления, предварительно сохранённые в `old-code`.
5. Выполняется `install.sh --existing --no-firewall`, включая HTTPS, авторизацию и проверки протоколов. Настройки firewall обновление не меняет. После успеха записывается commit в `data/release.json` для страницы обслуживания.

Одновременные обновления блокируются. Копии автоматически не удаляются. Предварительный запас места под состояние — две его несжатые величины плюс резерв; это не оценка полного размера всех Docker-образов. Перед загрузкой образов отдельно проверяются место/inode для установки, Docker и стандартного `/var/lib/containerd`. Для нестандартного хранилища containerd проверьте его файловую систему самостоятельно.

В Git-установке первая команда откажется перезаписывать изменённые отслеживаемые файлы. После обновления код контролируется собственным манифестом хешей, без изменения Git-истории; `git status` может показывать применённые обновлением изменения. Не смешивайте этот механизм с `git pull`/`reset` на сервере. Локальные правки управляемых файлов нужно отдельно сохранить и согласовать; `.env` и данные пользователей проверкой кода не блокируются. В старой архивной установке исходные локальные правки невозможно достоверно отличить от версии проекта, поэтому заменяемые файлы сохраняются в `old-code`.

## Если обновление прервалось

Исправьте конкретную причину и повторите ту же команду. Сохранённая транзакция продолжит **тот же commit**, без повторного создания пользователей или сброса состояния. Если на GitHub уже появились другие изменения, следующий запуск после завершения текущего обновления получит их.

При недоступном GitHub после начала применения можно продолжить локально:

```bash
sudo python3 /opt/freenetvpn/.updates/updater.py --root /opt/freenetvpn
```

Для продолжения загрузки образов/пакетов интернет всё равно может потребоваться. Если ошибка возникла после остановки, часть сервисов может оставаться остановленной. Не удаляйте `.updates/pending.json`, `.env` или `data`. Неудачная новая версия не приводит к автоматическому откату пользовательского состояния: после её запуска могли появиться новые пользователи.

## Явный откат

Найдите ID в выведенном пути резервной копии или `sudo ls -1 /opt/freenetvpn/.updates`. Подставьте его вместо `ID`:

```bash
sudo python3 /opt/freenetvpn/.updates/ID/updater.py --root /opt/freenetvpn --rollback ID --restore-state
```

`--restore-state` явно означает возврат **и кода, и пользователей/настроек на момент копии**. Изменения после этой даты перестанут быть активными. Перед откатом текущее состояние сохраняется в `ID/rescue-.../state.tar.gz`, а исходные каталоги перемещаются туда же без удаления. Их можно восстановить отдельно в чистую установку; автоматического объединения пользователей разных копий нет.

Откат повторно применяет прежний установщик и проверяет сервисы. Он не откатывает системные пакеты, firewall или ядро и не гарантирует работу без доступа к реестрам образов. Копия состояния не включает воспроизводимый Docker volume `caddy_config`; сертификаты Caddy находятся в `data/caddy` и включены. Для полного восстановления на другой машине используйте [инструкцию восстановления](recovery.ru.md). Проверка подключения с внешнего клиентского устройства остаётся обязательной после обновления/отката.

## `no space left on device` при скачивании

Это недостаток места, inode либо квоты в хранилище Docker/containerd, а не задержка DNS зоны сайта:

```bash
df -h / /var/lib/containerd
df -i / /var/lib/containerd
sudo docker system df
sudo apt-get clean
```

Повторите `df` после очистки. Если места всё ещё мало, увеличьте диск VPS или осознанно удалите ненужный кэш. Не удаляйте `/var/lib/containerd` вручную и не выполняйте `docker system prune --volumes`. Не удаляйте VPN-данные и последнюю резервную копию ради установки. Когда место появится, для незавершённой установки выполните `cd /opt/freenetvpn`, затем `sudo bash install.sh --existing`; для незавершённого обновления — команду обновления выше.

`--env-file /opt/frenv` не соответствует штатному пути `/opt/freenetvpn/.env`. Если это действительно исходный вывод, проверьте версию `tools/manage.py` и наличие `.env`, не печатая его содержимое. В показанном сбое Docker уже начал загрузку образов и сообщил нехватку места — это установленная причина остановки.
